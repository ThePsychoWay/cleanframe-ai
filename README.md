# CleanFrame AI

AI-powered video restoration: remove unwanted visual overlays (logos, text, timestamps) from videos you own or have permission to edit.

> Only remove overlays from content you own or have permission to edit.

## Run on your computer (no API, no Docker)

Double-click `Start CleanFrame.bat` (Windows) or `Start CleanFrame.command` (macOS), or run `python run_local.py`.
The site opens at http://localhost:3000.

Needs Python 3.11+, FFmpeg and Node.js 20+. No API key, account, PostgreSQL, Redis or cloud storage: it uses a SQLite file and
the disk, and runs jobs on threads in the API process. Everything stays on your computer, and it is tuned for low memory
(`--memory-mb`, `--workers`). Details: [docs/LOCAL.md](docs/LOCAL.md). Short checklist: [docs/CHECKLIST.md](docs/CHECKLIST.md). From a phone on the same Wi-Fi: `python run_local.py --lan` (or double-click *Start CleanFrame for Phone*).

## Configuration

Copy `.env.example` to `.env` and fill in the values. Secrets are never hardcoded.

## Develop

```bash
# backend (Python 3.12+)
cd backend && pip install -r requirements-dev.txt
alembic upgrade head          # needs DATABASE_URL
uvicorn app.main:app --reload # needs JWT_SECRET (32+ chars), DATABASE_URL and the storage settings
celery -A app.workers.celery_app worker -Q cpu,gpu   # analysis, tracking and renders; needs Redis (or set CELERY_EAGER=true)
# with a GPU: run one worker per queue instead, `-Q cpu` and `-Q gpu` (RENDER_QUEUE=auto sends local/video engines to gpu)

TEST_DATABASE_URL=postgresql+psycopg://user@localhost:5432/cleanframe_test pytest   # same suite on PostgreSQL (the test database is wiped)

# frontend
cd frontend && npm install && npm run dev
npm test
```

## Uploads

Videos never pass through the API. The browser asks the API for a presigned URL per part, sends 8 MiB parts
straight to object storage (three at a time, with retries), and the API verifies the byte total before
completing. A worker then reads the file with `ffprobe`, records its real properties, and builds a small preview copy and thumbnail for the editor. Choosing the same
file again after a dropped connection resumes from the parts storage already holds.

With a production S3 bucket, add a CORS rule that allows `PUT` from your app's origin and exposes the
`ETag` header, or the browser cannot read the receipt for each part. The bundled MinIO is configured for this.

## Editor

`/editor/{id}` opens once a project reaches "Ready to mark overlays". You mark areas on the preview with
rectangle, polygon, brush and eraser tools, add keyframes to move or reshape an area over time, track them through
the video, and save. The preview is a lower-resolution, silent copy; masks are stored as fractions of the frame, so
they apply to the original video unchanged.

"Remove Watermark" queues a background job (Celery + Redis) and shows its real progress: the step the worker has
reached, frames finished, speed, and time left for the rebuilding step. The job can be cancelled; the finished result
is verified before it is kept, and "Edit marks" reopens a finished video for changes. `AI_PROVIDER=auto` first tries to take a fixed semi-transparent logo off exactly (it measures the logo from the video and inverts it, so the real pixels come back, even on a still camera); if the mark isn't that, it falls back to the reconstruction below and says which was used. `AI_PROVIDER=reconstruct` rebuilds the marked area from the real pixels in other frames of your own video (no blur, no
model needed) and says how much was rebuilt and how much, if anything, was generated by LaMa. A mark that never moves
on a camera that never moves hides the same pixels in every frame; that case needs the LaMa fallback (an ONNX model
file you supply) and the result is then a plausible fill, not the original. With `AI_PROVIDER=dev` the picture is
blurred by a development engine; that is stated wherever the result is shown. See ARCHITECTURE sections 6b and 6c.

## Result

`/result/{id}` shows "Your restored video is ready." with a before/after view: a draggable divider between the
original and the restored video, zoom, scrubbing and frame stepping, with both videos kept on the same frame. Download
MP4 uses a signed link that works for five minutes and saves the file under a safe name; Delete project asks first and
removes the stored files. The original side is the editor's lower-resolution preview copy. Details in
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) section 7b.

## Security, retention and logs

Uploaded videos and their results are deleted automatically 48 hours (`VIDEO_RETENTION_HOURS`) after the last upload or
render, by a scheduled sweep (`celery -A app.workers.celery_app beat`; run exactly one) and by a check on every read, so
access also stops at the deadline. Sign-in, uploads, rendering and downloads are rate limited (Redis; production refuses to
start without it), files are checked for being video before any worker touches them, and the web app and API send a
Content-Security-Policy and the other standard headers. Set `NEXT_PUBLIC_STORAGE_ORIGIN` to the storage address (for example `http://localhost:9000` for the bundled MinIO) when you run
`npm run build` (it is read at build time): a production build only lets pages talk to https storage otherwise, and uploads to
plain-http storage are blocked. Logs are one JSON object per line with request and job ids, and contain no video content, file names, cookies
or signed-link credentials. Rules, messages and known limits: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) section 8.

## Run with Docker

```bash
cp .env.example .env          # fill in the passwords, JWT_SECRET and storage keys
docker compose --env-file .env -f docker/docker-compose.yml up -d --build                 # postgres, redis, minio, api, worker (cpu), beat (retention sweep), web
docker compose --env-file .env -f docker/docker-compose.yml --profile gpu up -d --build   # plus a GPU worker (needs the NVIDIA container toolkit)
```

The compose file passes `docker compose config`. The images (`docker/backend.Dockerfile`, `docker/frontend.Dockerfile`) have
not been built or run: the one environment they were prepared in could start a Docker daemon but could not pull any base
image. `--env-file .env` is needed because the web app's addresses (`NEXT_PUBLIC_*`) are compiled in at build time; change
them and rebuild with `up -d --build web`. Without Docker: `npm run build && npm start`.

Capacity numbers and how to measure them: `docs/ARCHITECTURE.md`, Phase 24 (`scripts/load/`). On a 2-core machine two worker
processes were the useful limit; a render's memory grows with the size of the marked area (about 2.3 GB for a 1550x530 px mark, down from 3.0 GB; see docs/LOCAL.md).

In production, run `python -m app.storage.provision` once so the bucket expires orphaned files and unfinished uploads itself. For
upload malware scanning set `MALWARE_SCAN=clamav` and `CLAMAV_HOST`, and start the `clamav` service with `--profile scan`
(see `.env.example`); scanning is off by default and fails closed when on.
